# Development priorities

I’m looking for help turning a working development runtime into a project that others can evaluate and contribute to confidently.

| Priority | Outcome I want | Useful contributions |
| --- | --- | --- |
| Reproducible setup | A clean clone can be validated without my workstation | Windows setup reports; Linux/macOS build and test results; dependency checks |
| Retrieval quality | Relevant facts retain negation, exceptions, provenance and uncertainty | Synthetic difficult queries, conflicting evidence and abstention cases |
| Honest token accounting | Complete task costs are compared with equal answer quality | Paired evaluations with actual usage, acquisition and rework costs |
| Lifecycle reliability | Deleted or stale evidence cannot return through caches or restores | Tombstone, restore, source-change and index-recovery regressions |
| Client integration | Explicit, scoped MCP setup with clear resource costs | Client compatibility reports and one-host/multiple-project design review |
| Operational reliability | Predictable behaviour under sustained load and recovery | Longer synthetic soak tests, backpressure and interrupted-write cases |
| Production foundations | A reviewed identity, key-custody and deployment design | Threat-boundary analysis and narrowly scoped proposals before implementation |

I do not attach delivery dates or production guarantees to these priorities. I prefer small, validated improvements that preserve the project’s privacy and authority boundaries.
